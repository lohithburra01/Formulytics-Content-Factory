Lesson 1: Your race weekend is a workflow, not an agent

About 5 minutes · Mission: a reliable Austin weekend you understand and can explain in an interview

The problem

Every weekend so far was one long chat. The AI decided what to do next, so it did it differently each time. That cost about 53 corrections over 13 sessions.

The idea

Anthropic, the company that makes Claude, separates two kinds of AI systems:

"Workflows are systems where LLMs and tools are orchestrated through predefined code paths."
"Agents ... are systems where LLMs dynamically direct their own processes and tool usage."
— Building effective agents

Your weekends were run like an agent: the AI chose the path. They should run as a workflow: the path is fixed in code, and the AI is only one step inside it.

Gates

Between steps you put checks that stop bad work:

"You can add programmatic checks (see "gate" ...) on any intermediate steps" — same article

A gate doesn't depend on anyone remembering a rule. It runs every time.

Austin as a workflow

1 Resume          code    reads the map: "Austin, step 5"
2 Get data        code
3 Track shape     code  + YOU approve
4 Racing line     code    GATE: on track? every apex?
5 Car setup       AI    + YOU approve
                          GATE: every number has a source?
6 Simulate        code    GATE: matches practice? engine unchanged?
7 Preview         code  + YOU approve
8 Render          code    GATE: zoom 28? no deletes?
9 Save            code

The AI appears once (step 5). You appear three times. Gates catch the rest.
