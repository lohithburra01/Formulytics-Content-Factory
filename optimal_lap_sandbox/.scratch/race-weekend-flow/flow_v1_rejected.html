Austin GP: from "open Claude" to the video

The same 9 stops every race weekend. Follow the line down.

Code runs it AI thinks You decide Auto-check blocks bad work
  1. 1

    Resume

    Code

    You open Claude. It reads one small map and tells you: "Austin, we're at step 5, last decision was X." No re-reading old chats.

  2. 2

    Get the data

    Code

    Downloads last year's qualifying lap and this weekend's practice laps.

  3. 3

    Build the track

    CodeYou

    Turns the circuit drawing into a road with edges. You look at one picture and say "shape is right."

  4. 4

    Racing line

    Code

    The optimiser draws the fastest line and saves it as one file, a "plug" that any optimiser can produce.

    Blocks if: the line leaves the road or misses an apex.
  5. 5

    Car setup

    AIYou

    The only creative step. The AI suggests drag, downforce and grip numbers, and each number must say where it came from (telemetry, FIA, or a paper). You approve them.

    Blocks if: a number has no source or is outside a sane range.
    Tool: Pydantic checks the numbers.
  6. 6

    Simulate the lap

    Code

    Drives the car around the line and gives the lap time and speed trace.

    Blocks if: the speeds don't match practice, or someone broke the engine.
    Tool: pytest + pre-commit run the checks automatically.
  7. 7

    Quick preview

    CodeYou

    A short, low-quality clip in seconds. You say "looks right" before wasting time on the full render.

  8. 8

    Render the video

    Code

    Full-quality optimal-lap video.

    Blocks if: zoom isn't 28, or anything tries to delete a file.
    Tool: Claude Code hooks enforce the rules.
  9. 9

    Save what happened

    Code

    The numbers and decisions get saved to the map and git, so next weekend starts at step 1 with everything known.

  10. 🏁

    Austin video done

    The whole path is run by LangGraph: it walks steps 1 to 9 and pauses at the three orange stops for you.
