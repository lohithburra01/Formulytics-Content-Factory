# Python packages for fast aerodynamics (VLM / panel / lifting line / vortex particle / neural / wake) for an F1-car-in-ground-effect lap simulation

Method of this sweep (2026-10-26): PyPI JSON API checked for ~70 candidate names; GitHub REST search over topics vortex-lattice(-method), panel-method, vortex-particle-method, uvlm, lifting-line plus keyword searches; 26 repos shallow-cloned and grepped for `ground effect / ground plane / method of images`, and the last commit date read with `git log`. Then web searches on validation literature. The web-search budget ran out after about 20 searches, so some items below are marked UNVERIFIED (from prior knowledge, not checked this session). "Last activity" is the last commit (git) or last PyPI upload.

## Q1. Catalogue: which fast Python aero packages exist and what can they do?

### Takeaway
Only a handful of maintained Python packages model 3D lifting surfaces with a real ground plane: **PteraSoftware** (steady + unsteady ring VLM, free wake, method of images in all solvers), **OpenAeroStruct** (VLM, `groundplane=True`, plane tilted with alpha, but needs symmetry and no sideslip), **AVL through AeroSandbox's `AVL` class or AVLWrapper** (Z-symmetry image plane, which is the classic approach), and the **Katz–Plotkin `VORING`** port. AeroSandbox's native VLM and lifting-line solvers do **not** model ground effect. Its 2D multi-element inviscid panel solver does. The only package that gives free-wake vortex positions over time (usable as "wake trails") and also has ground effect is PteraSoftware. Nothing in pure Python does a fast panel method on a full car body with ground effect, wake and attitude. The car body would need pyapm, LovelacePM or PyPan, each with a hand-added image mirror.

### Cited Findings

**Tier A: maintained, 3D, directly relevant**

1. **PteraSoftware**: https://github.com/camUrban/PteraSoftware, `pip install pterasoftware` (PyPI v5.1.0, uploaded 2026-07-15; last git commit 2026-10-19; 272 stars).
   - Solvers: steady horseshoe VLM, steady ring VLM, unsteady ring UVLM, aeroelastic UVLM (beta) and free-flight UVLM coupled to MuJoCo 6-DOF (beta). The UVLM supports fixed (prescribed) and free wakes, with vortex aging, and loads by Kutta–Joukowski or Katz–Plotkin pressure integration. — [README](https://github.com/camUrban/PteraSoftware)
   - Ground effect: "All three solvers support surface effects (e.g., ground effect) via the method of images." There is a shipped example `unsteady_ring_vortex_lattice_method_solver_static_ground_effect.py`, and the README hero animation is "Flapping Wings in Ground Effect". — README and repo examples (grepped locally)
   - Multi-body: an airplane holds one or more wings. Since v2.0 a simulation can hold more than one airplane, so front wing, rear wing and beam wing could be separate wings or "airplanes". — [README](https://github.com/camUrban/PteraSoftware)
   - Speed claim: "Most steady simulations take under a second, and most unsteady simulations take under a minute", using JIT and multi-core. — README
   - Wake output: the solver stores wake ring-vortex vertices for each time step (`_output_rendering.get_wake_ring_vortex_surfaces` builds `wake_ring_vortex_vertices` from `solver.list_num_wake_vortices[step]`). So the positions of free-wake vortex rings are reachable for each step and could be drawn as wake trails. This is a private/internal API, from a local source grep.
   - Python 3.11–3.14. Validation against experimental data from a flapping-wing robot (WashU): "simulated results agreed with the experimental trends and magnitudes of net lift with good accuracy". — [WashU report](https://openscholarship.wustl.edu/mems500/149). A later report claims the solver became more than 3x faster. — [WashU](https://openscholarship.wustl.edu/mems500/135)
   - The package is designed for flapping wings. Thick-body (fuselage or car body) panels are not supported: lifting surfaces only.

2. **AeroSandbox (ASB)**: https://github.com/peterdsharpe/AeroSandbox, `pip install aerosandbox` (v4.2.10, 2026-07-05; last commit 2026-10-07).
   - Native 3D solvers in `aerodynamics/aero_3D/`: `vortex_lattice_method.py`, `lifting_line.py`, `nonlinear_lifting_line.py`, `aero_buildup.py`, `linear_potential_flow.py`, plus an `avl.py` wrapper. — git tree listing
   - Ground effect: **only** `AirfoilInviscid` (2D) has `ground_effect: bool`, which adds "a mirror image of the singularity elements, mirrored about the y=0 line". It accepts `Airfoil | list[Airfoil]`, so it handles **2D multi-element sections in ground effect**. The 3D VLM, LL and AeroBuildup source contains no ground-effect code (grep). For 3D ground effect, ASB passes `ground_effect=True, ground_effect_height=...` to **AVL**, "mirroring the airplane about a ground plane (using AVL's Z-symmetry)". — source `aero_2D/airfoil_inviscid.py`, `aero_3D/avl.py`
   - Steady only. Wake is not a free wake; the VLM uses fixed horseshoes (UNVERIFIED detail). ASB is differentiable/optimizable through CasADi.

3. **NeuralFoil**: https://github.com/peterdsharpe/NeuralFoil, `pip install neuralfoil` (v0.3.3, 2026-07-11).
   - Physics-informed neural net trained on XFoil (tens of millions of runs). Reports a single run at about 1.2 ms (xxsmall model), 8–1000x faster than XFoil at equal accuracy, mean relative drag error 0.37% on simple cases and 2.0% on a test set with post-stall and transitional cases. Its "ground truth" is XFoil, not experiment. — [arXiv 2503.16323](https://arxiv.org/abs/2503.16323v1)
   - **2D, single element, free air only: no ground effect and no multi-element.** It is useful as the viscous section-polar source for a nonlinear lifting line or VLM strip correction (ASB's AeroBuildup and NL-LL already use it).

4. **OpenAeroStruct (OAS)**: https://github.com/mdolab/OpenAeroStruct, `pip install openaerostruct` (v2.12.0, 2025-10-06).
   - VLM plus a beam FEM in OpenMDAO, with gradients. Ground effect is set with `groundplane: True` per surface and an input `height_agl`. The mirror plane is "parallel to the freestream (influenced by angle of attack)", which OAS says is more correct than AVL's x-y mirror deep in ground effect or at high alpha. **Symmetry must be on and crosswind (beta) cannot be used with ground effect**, so yaw is not possible. The docs say results agree with Phillips & Hunsaker lifting-line ground-effect predictions. — [OAS ground-effect doc](https://mdolab-openaerostruct.readthedocs-hosted.com/en/latest/advanced_features/ground_effect.html)
   - Steady, fixed wake. The no-sideslip limit is a problem for yaw that varies frame by frame. Roll asymmetry also breaks the required symmetry, so it is effectively ruled out for cornering.

5. **AVL via Python**: AVLWrapper https://github.com/renoelmendorp/AVLWrapper, `pip install avlwrapper` (v0.6.0, 2026-10-09). There is also an older fork jbussemaker/AVLWrapper (2023), and AeroSandbox's `asb.AVL`.
   - AVLWrapper exposes `z_symmetry` + `z_symmetry_plane`, written as AVL's `iYsym iZsym Zsym` line. That is AVL's ground image plane. — source `avlwrapper/model.py`
   - AVL itself is Fortran (MIT, Drela), an extended VLM with slender bodies. It is steady with a fixed wake and needs the avl.exe binary. Windows binaries exist (UNVERIFIED this session). The Y-symmetry flag must be off to have yaw.
   - **Pitfall:** AVL's x-y mirror ignores alpha. OAS argues this is "not strictly correct" deep in ground effect or at high alpha. — [OAS doc](https://mdolab-openaerostruct.readthedocs-hosted.com/en/latest/advanced_features/ground_effect.html)
   - Related: brio50/AVL-Aero-Tables (Python, 2026-08) generates aero lookup tables with AVL ("simulate windtunnel testing"). — GitHub search result https://github.com/brio50/AVL-Aero-Tables

6. **VortexStepMethod (VSM)**: https://github.com/ocayon/Vortex-Step-Method (not on PyPI; install with `pip install -e .`; last commit 2026-10-08; MIT). Julia port at https://github.com/OpenSourceAWE/VortexStepMethod.jl (2026-10-21).
   - A lifting line solved at 3/4 chord, coupled to 2D viscous polars (inviscid, CFD or an ML airfoil model). Built for low-aspect-ratio, swept and anhedral kites. Includes stability derivatives and a trim solver, and uses numba. — [README](https://github.com/ocayon/Vortex-Step-Method)
   - **Ground effect: not implemented.** `docs/Wake.md` lists "Ground Effect Wake ... Image vortex systems" only under advanced/future wake models, and the `.py` source has no ground code (grep). The wake is steady and fixed. It is well suited to low-AR wings such as an F1 rear wing, but a ground image would have to be added by hand.

7. **pyvlm (Xero64)**: https://github.com/Xero64/pyvlm, `pip install pyvlm` (v0.0.13, 2026-10-24); and **pyapm (Xero64)**: https://github.com/Xero64/pyapm, `pip install pyapm` (v0.0.4, 2026-10-24).
   - pyvlm is a steady VLM. pyapm is a 3D "Aerodynamic Panel Method" (thick surfaces from airfoil sections). Both are defined in JSON, and the "mirror" keyword is spanwise y-symmetry, not ground. **No ground-effect keyword was found** (grep). Both are actively developed but low-star (8), and their documentation is thin. pyapm is one of the few maintained Python 3D thick-panel codes, so it is a candidate for a car body if the user adds an image body. Speed has not been measured.

8. **MachUpX (USU AeroLab)**: https://github.com/usuaero/MachUpX (138 stars; last commit 2024-05-23; install from GitHub, not PyPI under `machupx`).
   - Goates–Hunsaker general numerical lifting line for multiple lifting surfaces, nonlinear with section polars, multiple aircraft per scene, steady. **No ground-effect support found** in source or docs (grep). Phillips & Hunsaker did publish lifting-line ground-effect theory ("Lifting-Line Predictions for Induced Drag and Lift in Ground Effect", cited by the [OAS doc](https://mdolab-openaerostruct.readthedocs-hosted.com/en/latest/advanced_features/ground_effect.html)), so an image system is straightforward to add. Sibling: **Pylot** https://github.com/usuaero/Pylot is a real-time lifting-line flight simulator (2022). — [MachUpX README](https://github.com/usuaero/MachUpX)

9. **PanelAero (DLR)**: https://github.com/DLR-AE/PanelAero, `pip install PanelAero` or conda-forge (54 stars; last commit 2025-11-10).
   - VLM plus Doublet Lattice Method (frequency-domain unsteady, for flutter). AICs are validated against MSC.Nastran. It is a library that returns AIC matrices, not a full solver. The `mirror` hits in the grep are y-symmetry. **No ground plane.** — [README](https://github.com/DLR-AE/PanelAero)

10. **KatzPlotkinPy**: https://github.com/alwinw/KatzPlotkinPy (last commit 2026-03-25). A Python port of the Fortran programs in Katz & Plotkin's *Low Speed Aerodynamics*. This includes **`VORING`, "VLM for rectilinear surfaces (with ground effect)"** (§12.3), plus 2D source, doublet and vortex panels and time-stepping codes. The README table marks which programs are ported to Python and which are still Fortran-only. VORING is ticked Fortran, with Python apparently pending (from the README table). Joseph Katz is the main author of race-car aerodynamics textbooks, so this is the textbook baseline.

### Inferences
- **Best single fit for "car fixed, moving ground, wake trails, attitude per frame": PteraSoftware.** It is the only maintained Python solver found that combines free wake (vortex positions you can draw), a ground image, multiple wings and arbitrary operating points. Ride height, pitch and roll would be set by repositioning the geometry relative to the image plane, and yaw by sideslip. The image method gives a "moving ground" boundary for free, since an image wall carries no boundary layer, which is what a rolling road approximates. Seconds to under a minute per case fits a weekend batch. Risks: the free wake can pass near or under the ground image, and the code was tuned for flapping wings.
- **For a steady per-frame map (downforce vs ride height, pitch, roll, yaw):** AeroSandbox + AVL (Z-symmetry) or OAS are viable, but OAS bans sideslip and AVL's image plane does not tilt with alpha. A precomputed lookup table over attitude (as in AVL-Aero-Tables) evaluated per frame is the cheapest route.
- **Multi-element wing sections in ground effect:** use AeroSandbox `AirfoilInviscid(list_of_airfoils, ground_effect=True)` or the ollebompa tool for 2D, then sweep or strip-correct in 3D. Inviscid methods will miss the downforce drop at very low height that Zerihan & Zhang measured (flap separation and vortex breakdown; see Q2).
- **Car body and underfloor:** no fast Python tool models a thick body plus ground plus floor venturi convincingly. pyapm, LovelacePM or PyPan with a mirrored body is the only Python option, and a potential-flow floor will over-predict without separation and diffuser modelling.
- **Visual wake trails:** a separate cheap Lagrangian layer (vortex particles seeded from the VLM/UVLM wake filaments, e.g. in Taichi or numba) is likely more practical than a validated VPM. No Python VPM with solid-wall ground support was found.

### Gaps
- Per-case timings for F1-like meshes (front + rear + beam wing, around 2000 panels) were not measured for any package. Only PteraSoftware's own claim exists.
- Ground-effect support in SHARPy UVLM, VortexLattice.jl and VSPAERO was not verified (search budget exhausted).
- Windows behaviour of SHARPy, xfoil-python and the MachUpX install, and AVL binary availability, were not verified this session.
- Whether PteraSoftware's free wake stays stable when wake panels approach the image plane at F1 ride heights (h/c around 0.1–0.3) is unknown.

## Q2. How well do fast methods (VLM / panel / lifting line) reproduce race-car wing-in-ground-effect downforce vs CFD or tunnel data?

### Takeaway
I found **no published study validating a VLM, panel or lifting-line code against CFD or tunnel data for an open-wheel race-car front wing in ground effect**. Validation exists for (a) VLM in ground effect on aircraft and WIG wings (AVL, Cranfield 2024; a Korean free-wake VLM with endplates vs wind tunnel), (b) a modified discrete vortex method compared with Zerihan & Zhang's single- and double-element inverted wings, and (c) high-fidelity CFD benchmarks (the Imperial Front Wing). The canonical experimental data for checking any fast tool are Zerihan & Zhang's moving-ground tunnel tests: downforce rises as height falls, then plateaus or drops at low height because of separation and vortex breakdown, which inviscid methods cannot capture.

### Cited Findings
- **Cranfield 2024**: VLM (AVL) applied to wings near the ground. Results were correlated with analytic formulations and benchmarked against public-domain experimental data. The case was an ekranoplan wing, not a race car. — [Cranfield DSpace](https://dspace.lib.cranfield.ac.uk/handle/1826/20872) (full text returned HTTP 403, so quantitative agreement was not read)
- **Korean study**: VLM with freely deforming wake elements for a wing in ground effect, compared with wind-tunnel data. It found **endplates augment the ground effect at small clearance**, which matters for F1 front-wing endplates. — [newnonmun listing](https://www.newnonmun.com/article=10628639) (only the snippet was seen)
- **Zhang & Zerihan (AIAA J., 2003), double-element inverted wing in ground effect**: tested in a low-speed tunnel with a moving ground. The flow is 3D toward the tip and quasi-2D near the centre, and the main element generates most of the downforce. As height decreases, downforce rises asymptotically, then **plateaus at low flap angles or drops at large flap angles**. — [Southampton eprints](https://eprints.soton.ac.uk/22605); [HKUST record](https://researchportal.hkust.edu.hk/en/publications/aerodynamics-of-a-double-element-wing-in-ground-effect/fingerprints/)
- **Zerihan PhD (Southampton, 2001)**: single- and double-element wings. Trends for the single element were predicted well by **RANS Spalart–Allmaras**, a CFD result rather than a panel-method one. — [Southampton eprints](https://eprints.soton.ac.uk/21339/)
- **DRDO Defence Science Journal (2020)**: a modified discrete vortex method for moment prediction, referencing Zerihan & Zhang's single and double inverted wings with endplates. The degree of agreement was not confirmed. — [DSJ PDF](https://publications.drdo.gov.in/ojs/index.php/dsj/article/download/16127/7507)
- **Cornering**: "The Effect of Cornering on the Aerodynamics of a Multi-Element Wing in Ground Effect" (Fluids, MDPI 2021) is directly relevant to yaw and roll per frame. Its method is CFD (not read in detail). — [MDPI Fluids 6(1):3](https://www2.mdpi.com/2311-5521/6/1/3)
- **Imperial Front Wing benchmark**: based on the McLaren 17D front wing and endplate, previously investigated experimentally. The authors note that F1 test cases in the open literature typically lack experimental validation. Wake vortex structures are the hard part. This is a high-fidelity reference, not VLM. — [Nektar++ F1 front wing](https://www.nektar.info/?p=1720)
- **Race-car wings with vortex generators in ground effect** (Kuya, Takeda, Zhang; J. Fluids Eng. 2009/2010): experiments and 3D steady RANS. Not fast methods. — [HKUST](https://aantc.ust.hk/publications/71/)
- **Image-plane correctness**: OAS states that AVL-style x-y mirroring ignores alpha and is "not strictly correct" deep in ground effect or at higher alpha. OAS tilts the plane with the freestream. Its ground-effect results are "consistent with" the Phillips & Hunsaker lifting-line predictions. — [OAS doc](https://mdolab-openaerostruct.readthedocs-hosted.com/en/latest/advanced_features/ground_effect.html)
- **Generic lifting-line ground effect**: done by mirroring all vortex elements, bound and free, at the ground plane. — [QBlade docs](https://docs.qblade.org/_sources/src/theory/aerodynamics/secondary_effects/ground_effect.rst.txt)
- **VPM ground modelling with ground panels** is active research (TUM thesis topic; APS DFD 2024), meaning it is not off-the-shelf. — [TUM](https://www.asg.ed.tum.de/fileadmin/w00cip/ht/stellenausschreibung/abschlussarbeiten/Ground-effect_modelling_using_VVPM.pdf); [APS DFD 2024](https://archive.aps.org/dfd/2024/s01/3)

### Inferences
- Expect fast inviscid methods to track the **trend** of downforce vs ride height at moderate h/c. They will **over-predict at low h/c** and miss the force-reduction regime that Zerihan & Zhang measured (separation and vortex breakdown). Calibration against real data is therefore needed. This fits the user's existing practice of fitting knobs to telemetry: for example, a per-element viscous correction from NeuralFoil-type polars, or a fitted low-height roll-off.
- The underfloor and diffuser, which produce most of a 2026 car's downforce, are outside what any of these tools validate.
- A credible self-validation path is to run PteraSoftware or AVL on the Zerihan & Zhang single-element (Tyrrell 026-type) geometry and compare with the published CL vs h/c curves before trusting F1 numbers.
